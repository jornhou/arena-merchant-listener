# 使用说明（完整版）

## 一、怎么用

1. 双击 `start.bat`（默认模式）或 `start-lite.bat`（省电模式，常驻玩游戏用这个）。
2. 弹出一个置顶小窗，标题「战地行商 · 听声辨物」。窗里显示「等待拾取音…」说明已经在听了。
3. 最小化/切回游戏，正常拖动物资。游戏响起拾取音的一瞬间，小窗自动显示：

   只有两部分——「红金紫」和「概率」，其他一概不显示。

   - **红金紫**：按占格分行，格式相同的排同一行（横 6 格 / 竖 6 格 / 2×2 方块 / 单格 / 竖 2 格 …），
     格式不同就换行；每件只写名字和单价。红货、金货、紫件都在里面，比紫更小的件不显示。
   - **格型按钮**：小窗底部一排「全部 / 横 6 格 / 竖 6 格 / 本组其他格型」。
     点哪个 → 屏幕上只剩那种格子的货；点「全部」→ 回到全部显示。
     点过的会记住，下次开窗还是这个；想清掉就点「全部」。
     横 6 格 = 横着占 3×2 格；竖 6 格 = 竖着占 2×3 格。
     本组没有那种格子时，灰字写「这一组没有 竖 6 格」，不会假装有。
   - **概率**：这一声有多像（0–100%）。灰字带"偏低"的是低可信，别当准。

   举例：听到 01 的声音，小窗只有这几行：

   ```
   竖6格   鎏金羽宫 165万 · 黄金面具 160万
   横6格   黎明 160万 · 航天导航仪 155万 · "航天实验室"玩具箱 25.5万
   2×2方块 脑电装置 150万 · 法厄同之钟 150万 · 真实矩阵 150万 等7件
   单格    玉制手串 50.0万 · 金制钢笔 45.8万 · 金手表 8.1万 等8件
   竖2格   维塞尔日记 7.3万 · 单兵通讯装置 6.5万 · 手持分析仪 4.5万 等7件
   概率 78%
   ```

   你在游戏里看到那件东西占几格，就直接看对应那一行。只想对六格的：把底部
   「横 6 格」或「竖 6 格」点亮，屏幕上就只剩那一行。

4. 完整清单看 `item-list.txt`：17 段声音 → 每组先按占格分行列红金紫，再列全部 138 件
   （占格 / 名称 / 参考价 / 稀有度）。

   > 这里「红金紫」= r 值 6 / 5 / 4 三档，现在 `BIG_MIN_RARITY = 4` 全显示。
   > 只想留红货就把这个值改 6，只留红+金改 5。

5. 想自己验一遍识别准不准：

   ```bash
   python listen.py --check
   ```

   把 17 段样本灌进带噪声、不同音量、不同位置的窗口里各试 3 次，打印命中率（开发者本机 51/51）。

   ```bash
   python listen.py --selftest-all
   ```

   会把 17 段样本逐段真的播一遍、再录回来核对，打印命中数与错判清单
   （开发者本机 15–17/17，偶尔 05/08 这种很"虚"的音会飘，再拖一次即可）。

   环境噪声大时，加 `--boost` 用放大音量的副本测：

   ```bash
   python listen.py --selftest-all --boost
   ```

## 二、判断依据与"能到多细"

- 直接听扬声器正在播放的声音（WASAPI 回环录制），不占用麦克风，不影响游戏。
- 把你的拖动声与 17 段参考样本做波形 + 音色双重比对。
- 占格数据（宽×高，1×1 = 单格，1×2 = 竖两格，2×1 = 横两格，2×2 = 方块）来自声音图鉴
  逐件藏品的标注，138 件全部覆盖，所以工具能直接把"是什么 + 占几格"一起报出来。
- 边界要讲清楚：声音只区分到"组"这一级——同一组里的物品共用同一段拾取音，
  占格不同的物品也听不出区别。所以只能做到"给出这一组里符合该格子的那几件"，
  不能保证"就是那一件"。实际用法：听声定组 → 看轮廓（几格）在该组里二次筛选。

## 三、常见问题

### 1. 听不到 / 一直"等待拾取音"

- 小窗最下面一行会写"正在听：<设备名>"，先确认这个设备就是你游戏声音实际走的那个。
- 如果不对，双击 `select-device.bat`，它会列出本机所有可听的输出（回环）设备，
  输入前面的编号回车即可，程序会记住（写在 `%LOCALAPPDATA%\战地行商听声辨物\记住的设备.txt`），
  下次自动用这个。免安装版同样带这个入口。
  直接回车 = 清除记忆，回到"跟着系统默认输出走"。
- 也可以用命令行指定：`python listen.py --device 耳机`
  先看有哪些设备：`python listen.py --list`
- 游戏里连续放着背景音时最容易听；如果长时间完全没人出声，
  系统会暂时把音频设备休眠，这时第一声可能漏掉，再拖一次就正常了。
- 玩到一半拔耳机、切扬声器、系统默认输出被改走，不用重启：连续 3 秒读不到新音频，
  程序会判定设备掉了并自己重新接上。重连那一两秒的声音会漏掉，之后照常报。
  没手动选过设备时还会跟着系统默认输出走；手动选过就不跟随，只尝试你选的那台。

### 2. 结果不稳 / 老是不出结果

- 游戏音量别太小，系统音量保持正常（太低会认不出，尤其是 06/09 这种很"虚"的音效）。
- 微信/音乐/网页视频的声音会干扰，听之前尽量关掉。

### 3. 弹出别的组

- 看"相似度"和"次选"：相似度低于 0.45 的灰色结果是低可信，别当准。

### 4. 弹窗挡住游戏画面

- 直接把小窗拖到不挡视线的地方，它会记住这一次的位置；或者点"清空"只清内容。

## 四、备选参数

- 想省电、常驻一整天：`start-lite.bat`，等价于 `python listen.py --light`
  （比对间隔从 0.16s 放宽到 0.24s，CPU 占用约减半）。
- 游戏音量特别小时：`python listen.py --sensitivity high`
- 噪声很大、老误报时：`python listen.py --sensitivity low`
- 想换成耳机输出：`python listen.py --device <设备名片段>`

## 五、常驻与开销（开发者本机实测）

- 可以直接开着不管，内存稳定在 40MB 上下，不会越跑越大。
- CPU：默认模式约占单核 30%，省电模式约 15%（多核机器上就是整机的百分之几）。
  默认模式已把比对间隔放在 0.16s，再压就会让采集线程抢不到 CPU 而丢样。
- 只在你点的时候才启动：没有开机自启，也没有后台常驻服务，不点就什么都不跑。
- 关掉小窗 = 完全退出；连带那个黑框也不会留下（实测关窗后残留进程为 0）。

## 六、其它说明与边界

- 参考样本需要你自己准备，见 `docs/samples.md`。组名是按藏品内容归纳的；
  游戏内实际售价可能随版本浮动（数据为整理时的静态快照）。
- 同一次拖动里若同时含两三种物资，会先报最像的那一组，后面可能再报一次。
- 纯本地运行，不联网、不上传任何音频。
