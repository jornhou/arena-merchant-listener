# 准备声音样本（snd/snd01.wav … snd17.wav）

本仓库不附带游戏原声，版权原因见根目录 `NOTICE`。程序必须靠 17 段参考样本才能工作，缺样本会直接提示缺哪个文件。

## 你需要准备什么

- 17 个 wav，命名 `snd01.wav` 到 `snd17.wav`，放在本项目根目录的 `snd/` 下。
- 编号对应 `groups.json` 里的 `id`：`snd01.wav` = 第 1 组，`snd17.wav` = 第 17 组。
- 格式：**48000 Hz、16 bit**，单声道或双声道都行（程序会自动混成单声道）。
  采样率不是 48k 会直接报错退出，这一步别省。
- 每段只含一次拾取音，长度 0.5–1.5 秒即可，前后留一点静音没关系。

## 怎么录（两种办法，选一种）

### 办法 A：用程序自己的采集通道抓（最贴近真实链路，推荐）

1. 先让程序跑起来（需要临时绕过样本检查：随便放 17 个占位 wav 也行，或者先把 `groups.json` 备份后只留 1 组）。
2. 加上 `--record` 参数，程序会把采集到的声音存成 wav：

   ```bash
   python listen.py --record 抓到的一段.wav
   ```

3. 进游戏，在战地行商那里拖动一次物资，响起拾取音。停掉程序，得到一个或多个 wav。
4. 用 Audacity 之类切出干净的那一声，导出成 48kHz / 16bit，命名为 `sndNN.wav`。

这条路的好处是：录进来的就是程序之后要处理的那条链路（经过系统混音、回环、可能的音量增益），比外部录屏更接近实战。

### 办法 B：从录像里抽音轨

1. 开录屏（或游戏自带的录像），在行商处拖动物资，把拾取音录进去。
2. 抽音轨 → 切成单次拾取音 → 导出 48kHz/16bit wav → 重命名为 `sndNN.wav`。

要保证录的时候游戏音量和你实际游玩时一致，否则样本与实际音量不匹配，识别会变差。

## 编号怎么对上

打开 `物品对照表.txt`，每组开头都有 `No.01 小件杂货 · 电子首饰` 这样的行；`No.` 后面的数字就是文件名编号。如果你不确定某个拾取音属于哪一组，可以：

1. 先只放一段样本，跑 `python listen.py --check`，看它被认成哪一组；
2. 对照 `物品对照表.txt` 里那一组的物品清单，判断是不是你录到的那一堆东西。

## 准备好之后验证

```bash
python listen.py --check
```

它会把 17 段样本加噪声、改音量、移位各试 3 次，打印命中率。**17 段全对（51/51）才算样本合格**；如果某几段老是认错，多半是那几段样本切得不干净（混进了别的音效或人声），重切一次。

再跑真机验证：

```bash
python listen.py --selftest-all
```

会把样本依次播出来、再录回来核对。这一项受环境噪声影响，命中 15–17/17 都算正常，05、08 这类很"虚"的音偶尔会飘。

## 关于 snd_boost/

`--boost` 自检会去读 `snd_boost/`，那是给环境噪声大时用的放大音量副本，非必需。要用的话自己复制一份并适当增益，同样**不要提交到公开仓库**。

## 请不要把游戏音频提交到仓库

`.gitignore` 已默认忽略 `snd/*.wav` 和 `snd_boost/`。如果你 fork 了这个项目，也请保持这个忽略规则——游戏音频的著作权不在你我手里，公开分发有被下架的风险。
